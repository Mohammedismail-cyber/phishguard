# Data Notes

## Source
`data/urls.csv` is **synthetic**. It is generated by `data/build_dataset.py` (seed 42) and contains
2,000 URLs, balanced 50/50 between legitimate (label 0) and phishing (label 1).

- Legitimate URLs combine popular real-world domains with ordinary paths. A few legitimate URLs
  deliberately contain words such as `login` or `account` (for example `paypal.com/login`).
- Phishing URLs follow common patterns: raw IP hosts, `@` tricks, long hyphenated brand-plus-keyword
  domains, many subdomains, odd top-level domains, and deep paths.
- About 5% of labels are flipped at random so the task is not trivially separable.

## Limitations
- The same assumptions used to generate the data are used to design the features, so the measured
  accuracy is **optimistic** and shows that the pipeline works, not how well it performs on real traffic.
- Real phishing evolves quickly; attackers can imitate legitimate URL structure.
- Features are lexical only (no page content, WHOIS, DNS, or certificate data).

## Using real data
Any CSV with the columns `url,label` (1 = phishing, 0 = legitimate) works. Good sources:
PhishTank, OpenPhish (phishing URLs), the Tranco list (legitimate URLs), or the UCI/Kaggle
phishing URL datasets. Then run:

```bash
python -m src.train --input path/to/your.csv
```
